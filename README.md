# Taiwan Science Events — GitHub Pages edition

Static GitHub Pages site plus a scheduled GitHub Actions updater.

## Repository layout

- `dist/` — the complete static site published to GitHub Pages.
- `dist/data/events.json` — generated event data.
- `update_events.py` — event collector.
- `reports/latest.json` — updater diagnostic report generated by Actions.
- `.github/workflows/pages.yml` — daily update + Pages deployment workflow.

## First deployment

1. Create a GitHub repository and upload/push the contents of this folder to the `main` branch.
2. Open **Settings → Pages** and set **Source** to **GitHub Actions**.
3. Open **Actions → Update events and deploy Pages → Run workflow** once. This first manual run fetches the current data and deploys the site.
4. Later runs happen automatically every day at **06:15 Asia/Taipei**.

The project page URL will normally be:

`https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/`

All site resources use relative URLs, so the site works under a GitHub Project Pages subpath without editing the repository name into the source files.

## ASIAA mode

The workflow runs the updater with `--asiaa-access public-html`, matching the previously tested public-HTML mode. The updater still records the site's robots directives in its diagnostic report; HTTP success is not treated as authorization.

## Local update

```bash
python -m pip install -r requirements.txt
python update_events.py --asiaa-access public-html
```

For local viewing, serve `dist/` over HTTP rather than opening `index.html` directly, for example:

```bash
python -m http.server 8000 -d dist
```

Then open `http://localhost:8000/`.
